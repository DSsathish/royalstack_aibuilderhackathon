Where Gemini works, and where code decides

Gemini

  • Live speech-to-speech conversation, interruptible, with memory across visits
  • Tool-calling agent on Google ADK; tools are plain functions gated by mode
  • Product photo identification and the bag check at the exit
  • Multilingual search with embeddings over a keyword fallback
  • The rationale on every purchase-order draft
  • A normalizer agent that proposes how any CSV maps to the canonical schema

Code

  • Stock, prices and locations come only from tool results, never from the model’s memory
  • The screen renders only tool results: products, map, cart, receipt
  • Map highlights and cart adds are resolved deterministically after a search
  • Exit verdicts, discounts and points are rules and arithmetic inside transactions
  • Every stock change or order waits for the owner’s approval
  • Retries, low thinking budgets and schema-free JSON keep the model fast and cheap

The split is the design principle: the model talks, sees and proposes; code counts, decides and pays. That is what makes the agent trustworthy enough to run a shop’s stock.
